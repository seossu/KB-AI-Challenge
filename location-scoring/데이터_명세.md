# 데이터 명세 — AI 데이터 기반 최적 입지·금융 컨설팅 서비스

> KB AI Challenge / 주제 2. 코딩 시 참조하는 기준 문서.
> "무슨 데이터를 → 어디서 → 어떻게 가공해 → 추천하고 → 평가하나"의 확정본.

---

## 0. 제품 골격 — Pull / Push 2단 구조

한 고객의 생애주기를 두 단계로 덮는다. **두 시스템이 아니라 하나의 엔진, 두 개의 트리거.**

| | **Phase 1 — Pull (입지·자금 설계)** | **Phase 2 — Push (상권 워치독/조기경보)** |
|---|---|---|
| 계기 | 사용자가 조회 (온디맨드, 실시간) | 시스템이 감지 (월별 배치) |
| 대상 | 예비창업자 (진입 **전**) | 운영 중 자영업자 (진입 **후**) |
| 출력 | 입지 Top-N + 금융상품 추천 | 국면변화 **경고** + 금융 재추천 |
| KB 사업가치 | 신규 여신 origination | 관계 지속 + 추가 여신 (고객 LTV↑) |
| DCT 매핑 | 1회성 Sensing→Seizing→Transforming | **지속 S→S→T 루프** (진짜 dynamic capability) |
| 데모 방식 | 실시간 조회 시연 | "6개월 후" 시뮬레이션 |

**"동적"의 정의**
1. 추천이 1회성이 아니라 지속된다 (진입 후에도 관찰·재알림).
2. 상권 상태를 "좋다/나쁘다"로 고정하지 않고 **매달 갱신되는 확률**("지금 성장국면일 확률 71%")로 다룬다.

**스코프 정직성**: "실시간"의 실체 = 온디맨드 **즉시 응답** + 국면은 **월 1회 배치** 재추정. 초/일 단위 스트리밍 아님. 발표에서 명확히 못박는다.

## 1. 공통 데이터 레이어

### 1.1 기준 공간단위 — 소진공 상권 폴리곤

소스마다 공간단위가 다르므로 **하나로 통일해야 조인 가능**. 후보(추천 대상) 단위를 **소상공인시장진흥공단 상권 폴리곤(골목/발달상권)**으로 고정하고, 나머지 소스를 PostGIS 공간조인(`ST_Within`)으로 이 폴리곤에 매핑한다.

- 이유: "입지 후보" 개념에 자연스럽고, 매출·경쟁밀도·폐업률이 이미 이 단위로 제공됨.
- ⚠️ 사용자가 `preferred_region:"성수동"`을 주면 **성수동 안의 여러 상권 폴리곤을 비교**해 Top-N을 뽑아야 함. 후보 단위가 "성수동"보다 작아야 하며 상권 폴리곤이 그 역할.

### 1.2 소스 마스터 테이블

| 데이터 | 어디서 | 원본 공간단위 | 갱신 | 가공 방법 | Pull | Push |
|---|---|---|---|---|---|---|
| 유동인구(세그먼트) | 서울 열린데이터광장 생활인구 | 집계구 | 일 | 폴리곤 공간조인 → **20~30대·평일 점심/저녁** 필터 → 월집계 | 점수 | **추세감지** |
| 상권 매출·개폐업 | 소진공 상권분석 | 상권폴리곤 | 분기 | base 단위 그대로, 분기값 carry-forward | 점수 | **국면입력** |
| 카페 경쟁밀도·폐업률 | 소진공 업종별 점포수 | 상권폴리곤 | 분기 | 카페 점포수/폐업률만 추출 | 점수 | **경고입력** |
| 부동산 시세·임대료 | 국토부 실거래가 | 필지(점) | 수시 | 폴리곤 내 평균 → ㎡당 환산 → 월집계 | 점수 | **급등감지** |
| 교통 | 서울 열린데이터·지도 API | 점(역/정류장) | 고정 | 폴리곤 중심 기준 거리·개수 | 점수 | 정적 |
| 생활인프라 POI | 카카오/네이버 지도 API | 점 | 준고정 | 폴리곤 내 POI 카운트 | 점수 | 정적 |
| 배후인구 | KOSIS | 행정동 | 분기/연 | 폴리곤 포함 행정동 매핑 | 배경 | 배경 |
| 정책금융 텍스트 | 중기부·신용보증기금·소진공(+KB 크롤링) | 문서 | 수시 | 크롤링 → 벡터DB(RAG) 인덱싱 | **매칭** | **재매칭** |

### 1.3 소스 현실 조정 (별점 그대로 두면 안 되는 것)

- **한국부동산원 임대동향조사**: 권역 단위 표본조사라 성수동 세부 해상도 없음 → **국토부 상업용 실거래가로 임대료 대리(proxy)**. 부동산원은 권역 평균 배경값으로만 broadcast. "정확한 상가 임대료는 확보 한계 → 실거래 기반 추정"이라고 정직하게 스코프.
- **국세청 사업자등록**: 세부주소는 개인정보로 미공개(시군구 100대 업종 통계뿐) → 경쟁밀도·폐업률은 **소진공 상권분석을 메인**, 국세청은 보조.
- **KB 자체 상품**: API 미공개 가능성 높음 → 텍스트 크롤링 후 RAG. "실서비스화 시 KB 내부 상품 DB 연동 가능"을 전제로.

## 2. 스코어링 엔진 (Pull/Push 공유)

### 2.1 입력 파싱 — JSON을 계량 변수로

| JSON | 내부 변수화 |
|---|---|
| `target_customer:"20~30대 직장인"` | 유동인구를 **20~30대 × 평일 점심·저녁 세그먼트**로 필터 |
| `business_type:"카페"` | 경쟁밀도 = 카페 점포수, 폐업률 = 카페 업종 |
| `priority:["foot_traffic","low_rent"]` | 두 지표 가중치 부스트 |
| `capital + desired_loan` | 감당가능 임대료 상한 + 자금조달 한도 |
| `store_size_pyeong, parking, public_transport` | 하드필터 조건 |

### 2.2 정규화 — 방향 통일한 백분위(0~100)

각 지표를 서울 전체 상권 분포 대비 백분위로 환산.
- 높을수록 좋은 것(유동인구·매출·인프라·교통·배후인구): 그대로.
- 낮을수록 좋은 것(임대료·경쟁밀도·폐업률): `100 − 백분위`로 반전.
→ 모든 지표가 "클수록 좋음"으로 통일. (z-score보다 해석 쉬움: "유동인구 상위 12%")

### 2.3 base_score — priority 가중합

priority에 든 지표를 부스트 (가중치 합 = 1). 예시 가중치:

```
foot_traffic(priority) 0.30 | rent_inv(priority) 0.25 | competition_inv 0.15
| sales 0.10 | transit 0.08 | infra 0.07 | residential 0.05

base_score = Σ (weightᵢ × normalizedᵢ)
```

### 2.4 국면승수 — "동적"이 들어가는 지점 (무대 뒤)

```
multiplier   = 0.7 + 0.6 × growth_prob     (confidence 낮으면 1.0으로 무력화)
final_score  = base_score × multiplier
```
`growth_prob` = Markov Regime-Switching 모델의 성장국면 확률.
- 국면 정의는 **유동인구가 아니라 "소상공인 수익성"** 기준: `매출증가율 − 임대료증가율` 스프레드 등 복합지수를 단일 시계열로 만들어 MRS에 투입. (유동인구만 보면 젠트리피케이션에서 정반대 신호가 나옴.)
- 표본 18개월 미만 상권은 국면추정 skip, `confidence="low"` → 정적 지표만 사용.
- MRS는 국가단위 경기순환 기법이므로 관측윈도우(월별)·상태수(2-state)를 상권 미시단위에 맞게 조정해 적용(스케일 조정 명시).

### 2.5 워크드 예시 — 성수동 3개 상권

| 지표(정규화) | A. 성수카페거리 | B. 성수역 이면 | C. 서울숲 인근 |
|---|---|---|---|
| foot_traffic (20~30대) | 95 | 72 | 58 |
| rent_inv | 15 | 55 | 62 |
| competition_inv | 20 | 60 | 70 |
| sales | 90 | 65 | 55 |
| transit | 80 | 88 | 65 |
| infra | 85 | 70 | 68 |
| residential | 50 | 60 | 72 |
| **base_score** | **59.1** | **65.8** | **62.5** |
| growth_prob | 0.20 (쇠퇴) | 0.75 (성장) | 0.68 (성장) |
| multiplier | 0.82 | 1.15 | 1.11 |
| **final_score** | **48.5** | **75.7** | **69.2** |

**서사**: 카페거리(A)는 유동인구 1등(95)이라 순진한 툴이면 1등 추천. 그러나 사용자가 "낮은 임대료"를 priority로 걸어 임대료·경쟁밀도에서 깎이고(base 꼴찌), 국면도 쇠퇴(젠트리피케이션)라 승수로 더 눌려 **최종 꼴찌**. → **뜨는 이면상권 B**를 추천. "유동인구 최고 ≠ 최적"을 숫자로 증명.

## 3. Phase 1 — Pull: 추천·평가

### 3.1 데이터 흐름
```
입력 JSON → 성수동 안 후보 폴리곤 N개 → 공통 데이터 조립
→ 백분위 정규화 → 하드필터(감당불가 제거)
→ priority 가중합 = base_score → 국면승수 = final_score
→ Top-N → 자금격차 계산 → 정책금융 RAG 매칭 → LLM 설명
```

### 3.2 하드필터
- `rent_est`로 감당 불가한 임대료 상한 초과 상권 제거
- `store_size_pyeong` 확보 불가 상권 제거
- `parking` / `public_transport` 조건 미충족 제거

### 3.3 금융 추천 (두 번째 산출물)
```
총소요자금 = 보증금(rent_est×월수) + 권리금 + 시설비(평당×평수) + 초기운영비
조달가능   = capital + desired_loan
자금격차 gap = 총소요 − 조달가능

gap > 0  → RAG로 정책자금·대출 검색
매칭점수 = f(한도 ≥ gap, 금리↓, 자격요건 부합[업종·지역·창업여부])
국면 연동: 성장·진입 → 창업·시설자금 / 쇠퇴 → 경영안정·조기상환
```
예: 총소요 3.2억 − 조달 3억 = **gap 2천만원** → "소진공 창업자금(한도 7천, 2%대, 청년창업 요건)" 매칭 → LLM이 "왜 지금 이 상품인지" 설명.

### 3.4 평가
- **점수 산출** = 다기준 가중평가(2.2~2.4).
- **검증(방어카드)**:
  - 소진공 과거 데이터 **백테스트**: "2년 전 이 로직이 추천했을 상권이 실제로 매출·생존이 더 좋았나?"
  - 국면승수 유무 **ablation**.

## 4. Phase 2 — Push: 감지·경고·평가

### 4.1 데이터 흐름 (같은 엔진, 트리거만 다름)
```
사용자가 고른 상권 1개 → 매달 데이터 갱신
→ 국면확률 재추정 + 임대료/폐업률 추세 계산
→ [트리거 판정] → 경고 생성 → 금융 재매칭 → 푸시
```

### 4.2 트리거 조건 (계량화된 경고 규칙)

| 감지 | 조건 | 경고·추천 |
|---|---|---|
| 국면 전환 | growth_prob가 0.5 하향 돌파 | "쇠퇴국면 진입" + 경영안정자금 |
| 임대료 급등 | 임대료 MoM > 임계(예: +5%) | "임대부담 경고" + 조기상환 검토 |
| 경쟁 과열 | 카페 점포수 급증·폐업률↑ | "포화 경고" + 관망 권고 |
| 성장 확인 | growth_prob 지속 상승 | "확장 적기" + 시설·확장자금 |

### 4.3 평가
- **조기경보 리드타임**(event study): 경고가 실제 악화(폐업률 상승 등)보다 얼마나 앞섰나.
- 오탐(false alarm)·미탐(miss) 율.

## 5. 입력 JSON 스키마 (확정안)

```json
{
  "purpose": "창업",
  "business_type": "카페",
  "capital": 200000000,
  "desired_loan": 100000000,
  "preferred_region": "성수동",
  "target_customer": "20~30대 직장인",
  "priority": ["foot_traffic", "low_rent"],
  "store_size_pyeong": 20,
  "parking": true,
  "public_transport": true
}
```

**초안 대비 변경점**
- `store_size` 문자열("20평") → `store_size_pyeong` 숫자(조인·필터용).
- `desired_loan` 추가 (금융추천의 핵심 입력. 자기자본만으론 부족).
- `priority` enum 고정: `foot_traffic | low_rent | low_competition | transit | residential_base`.
- `target_customer`는 문자열로 두되 파이프라인에서 `{age:"20-30", time:"평일점심저녁"}`로 파싱해 유동인구 세그먼트에 연결.

## 6. 발표 방어 요약

- **AI다움**: 이질적 다중 소스를 종합 분석 + 자연어 근거 설명(주제 원문 "AI가 종합적으로 분석"에 정면 대응). 필요 시 비정형 텍스트(리뷰·SNS 버즈) 선행지표는 확장 옵션.
- **차별화 한 줄**: "남들은 한 시점 스냅샷, 우리는 **뜨는 상권/지는 상권**까지 국면으로 반영한다."
- **설명가능·이론기반 AI**: 금감원 후원 대회 → 블랙박스 대신 은닉상태·전이확률로 **왜 그렇게 추천했는지 설명 가능**한 화이트박스. Regime-Switching / DCT는 무대 뒤 신뢰성 근거로만 사용(무대에 econometrics 올리지 않음).
- **정직한 한계**: 임대료 해상도 한계(실거래 대리), 단일 상권 표본부족 시 국면판단 skip, Real Options는 "대기옵션" 관점만 정성적으로 차용.
